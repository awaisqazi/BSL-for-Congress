## 2. What counts as publishable

Publish only if the item states a verifiable fact AND you have a source link a reader can open. Qualifying:
- A dated event with place and an RSVP link (canvass, Ward Night change, town hall, screening, DSA event naming the 25th Ward or Byron).
  These go in `events.json` (section 5); add a news post too only if it is also news (a rally, a screening, a changed Ward Night).
- A filing or official deadline (Chicago Board of Elections; confirm on chicagoelections.gov or the campaign post citing it).
- An endorsement announced by the endorsing organization itself (link their announcement, not just our repost).
- A press piece about the campaign (link the piece itself).
- A campaign milestone the campaign itself announced.

Never publish:
- Anything inferred or reconstructed from a vague post, or any date/place you had to guess.
- Anything about opponents. Never name them, even to rebut.
- Fundraising goals framed as caps ("only $X to go"). Goals are floors.
- Promises, giveaways, event formats, or who speaks from where unless the campaign stated it in the post.
- Reposts of other accounts with no campaign tie.
- Amplifying fights that are not the ward's (the Pritzker exchange), the federal ballot-access suit, or personal/family news.
- Claims contradicting the site's verified facts (see `voice.md`; Chinatown is not part of the 25th; never state that anyone
  coordinated the ballot objections).
When in doubt, do not publish: list it in the report under "seen, not published".

## 4. Writing rules

Source of truth: `voice.md`. Short version:
- Speak as the campaign ("we"), about our own record. Press and endorsements are receipts, never the subject of a sentence
  ("The Tribune endorsed him" at most as a trailing receipt; never "X reported", "according to", "credits").
- Plain, front-porch, concrete: real addresses, dates, numbers. No adjectives like tireless/bold/champion. Byron is the organizer,
  the neighbors are the protagonist.
- No emdashes anywhere, English or Spanish. Use commas, colons, or a new sentence.
- Title: short (about 6 words). Summary: exactly one sentence. Body: two to four short paragraphs, no more.
- Every post ends with the standing ask, in the last body paragraph: knock doors with us. Do NOT add the Knock Doors pill or
  a link for it; the page template adds the pill.
- State only what the source states. No invented mechanics, giveaways, formats, speakers, or "free" anything.
- Spanish is real Spanish written for a Pilsen neighbor, not a word-for-word translation. Same facts, same warmth. Glossary:
  ward = distrito; Ward Night = Noche del Distrito; small business = pequeños negocios; tenants = inquilinos;
  property taxes = impuestos a la propiedad; affordable housing = vivienda asequible. Use "tú/ustedes" warmth, with accents and
  inverted punctuation. Standing planks, if needed, are fixed: "que paguen los ricos, que se financien las escuelas, alivio en
  los impuestos a la propiedad".
- Dates written out in both languages (October 17 / 17 de octubre). Times with AM/PM in English, 24h or "10 de la mañana" in Spanish.
- Read it aloud as Byron in a packed room. If it sounds like a press release, cut adjectives and add an address.
- News `expires` (optional, `YYYY-MM-DD`): set it for anything time-bound, to the event day (or last day of a window). After that
  day the post leaves the home strip but stays on `/news/`. Evergreen items (endorsement, press, milestone) omit `expires`.

## 4b. News posts: `src/data/news.json`

The file is a JSON array of posts. Required fields: `slug`, `date`, `kind` (`event`, `news`, `press`, `action`), `title`,
`summary`, `body`, `source`. Optional: `event`, `links`, `image`, `expires`. `title`, `summary` and `body` are `{en, es}`
(`body` is two to four plain-text paragraphs per language, no HTML or Markdown). `source` is `{label, href}`. `event` is
`{start, end, location, rsvp}`; `start`/`end` are `YYYY-MM-DD` or a full ISO time with the Chicago offset. `links` buttons are
`{label: {en, es}, href}`. Example (shape only, copy no facts from it):

```json
{
  "slug": "2026-10-18-petition-canvass-cermak",
  "date": "2026-10-12",
  "kind": "action",
  "title": { "en": "Petition canvass this Sunday", "es": "Caminata de firmas este domingo" },
  "summary": { "en": "One sentence.", "es": "Una oración." },
  "body": {
    "en": ["Paragraph one.", "Last paragraph ends with the ask: knock doors with us."],
    "es": ["Párrafo uno.", "El último termina con la invitación: toca puertas con nosotros."]
  },
  "event": {
    "start": "2026-10-18T11:00:00-05:00",
    "end": "2026-10-18T14:00:00-05:00",
    "location": { "en": "25th Ward IPO office", "es": "Oficina del 25th Ward IPO" },
    "rsvp": "https://actionnetwork.org/events/EXAMPLE/"
  },
  "links": [
    { "label": { "en": "Knock doors with us", "es": "Toca puertas con nosotros" }, "href": "/volunteer#signup" }
  ],
  "source": { "label": "Chicago DSA Southside Branch, Action Network", "href": "https://actionnetwork.org/events/EXAMPLE/" },
  "expires": "2026-10-18"
}
```

Rules that trip people up:
- `date` is the POST date (the day the campaign announced it), NOT the event date. The event date lives in `event.start`.
- Offsets: `-05:00` before Nov 1, 2026 and from Mar 14, 2027; `-06:00` in between.
- `source.href` must be a page where every fact in the post can be checked.
- Newest first: insert the new post at the top of the array. Same-day posts tie-break by file order (earlier in the file shows
  first), so put the newest of two same-day posts above the older one.

Load / insert / dump pattern (do not hand-edit commas):
```

python3 - <<'PY'

path = 'src/data/news.json'
posts = json.load(open(path, encoding='utf-8'))

assert all(p['slug'] != new['slug'] for p in posts), 'duplicate slug'
posts.insert(0, new)     # newest first
with open(path, 'w', encoding='utf-8') as f:
    json.dump(posts, f, indent=2, ensure_ascii=False)
    f.write('\n')

git diff --stat src/data/news.json    # only your additions should show
```

## 5. Events: `src/data/events.json`

Any dated shift the sweep finds goes here: a canvass, meetup, rally, Ward Night special, or a forum the campaign posts. Follow
`src/data/EVENTS-README.md` exactly. The home page Show Up block shows the next three dated shifts automatically (sorted by
`start`, expired ones drop off), and `/events/`, the volunteer This Week strip and the `.ics` calendar files read the same entry.
Do not touch any component to make an event appear.

Fields for a dated entry (all required unless marked):
- `id`: lowercase hyphens, unique, permanent. Convention `<kind>-YYYY-MM-DD-<place>`, e.g. `canvass-2026-10-18-cermak`.
- `kind`: `canvass`, `meetup` or `wardnight` for something you show up to (becomes a card).
  `deadline` or `election` for official dates (ledger, never a home card).
- `title` and `line`: `{en, es}`. Title is short ("Petition Canvass"). Line is one sentence saying what you do there.
- `start`: full ISO time with the Chicago offset (`2026-10-18T11:00:00-05:00`; `-05:00` before Nov 1, 2026 and from Mar 14,
  2027, `-06:00` in between). `end`: same format, or `null`. Deadlines with no time use `YYYY-MM-DD`; for a window, `end` is the
  last day.
- `location`: plain string for a proper name ("Cafe Latteaa"), or `{en, es}` when it translates. `address`: street address or
  `null`. State the address only; never claim a place is or is not in the ward.
- `rsvp`: the RSVP URL or `null`. `action`, matching the rsvp (exactly one button):
  - with RSVP: `{"en": "RSVP", "es": "Confirmar asistencia"}`
  - no RSVP: `{"en": "Tell us you're coming", "es": "Avísanos que vienes"}`
  - deadline/election: `{"en": "Add to calendar", "es": "Agregar al calendario"}`
- `sponsor`: the host as the source names it ("Chicago DSA Southside Branch"), or `null`.
- `source`: a full `https://` URL where every detail can be checked. `expires`: `YYYY-MM-DD`, the event day (last day of a window).
- Weekly standing shifts (`recurring: true`, `rule`) already exist for Ward Night and the Sunday canvass. Do not add more.

The README has a full example; the entry is the field list above in one flat object, with `title`, `line` and `action` as `{en, es}`.

Hard rules:
- An event without a source URL is NOT added. Every date, time, place, address, host and RSVP link must be in that source.
  Never invent a time, speaker, giveaway, food, format or who will be there. Missing detail: leave it out, or skip the event.
- Dedupe: same `start` + same `address` = same event. Skip it (or correct the existing entry if a fact changed).
- Deadlines and elections (`deadline`, `election`) go in ONLY when they come from the Chicago Board of Elections
  (chicagoelections.gov or its calendar), and that URL is the `source`. A campaign post alone is not enough.
- The NextUp ledger row (section 6) is added only for deadlines and multi-day windows, not for every canvass.
- If the event is also news, add a `news.json` post too (section 4b); the shift itself still lives here.
- Do not delete past entries in the sweep; the site hides them.

Same pattern as news, appended and sorted by the site (order in the file does not matter):
```
python3 - <<'PY'
import json
path = 'src/data/events.json'
ev = json.load(open(path, encoding='utf-8'))
new = { ... }            # full entry, shape above
assert all(e['id'] != new['id'] for e in ev), 'duplicate id'
assert all((e.get('start'), e.get('address')) != (new['start'], new['address']) for e in ev), 'same start + address'
assert new['source'].startswith('https://')
ev.append(new)
with open(path, 'w', encoding='utf-8') as f:
    json.dump(ev, f, indent=2, ensure_ascii=False)
    f.write('\n')
PY
```

## 6. Calendar ledger (NextUp.astro)

Add a row ONLY for a deadline or a multi-day window (filing week, objection period, vote-by-mail opening, early voting,
registration close), with a date and a source link. Do NOT add a row for an ordinary canvass, meetup or Ward Night: those
live in `events.json` and show on the home page and `/events/` by themselves. The deadline itself also goes in `events.json`
(section 5, kind `deadline` or `election`); the ledger row is the extra, hand-formatted copy. No date or no source: no row. Never add or
remove flyer cards (`.nextup-card`) in the daily sweep; those are hand-curated. Ledger rows only.

Insert the new `<li>` inside `<ul class="nextup-dates">` in CHRONOLOGICAL order by start date, copying this markup exactly:
```
<li class="nextup-date-row" data-past-after="YYYY-MM-DD">
  <span class="nextup-date" data-i18n="nextup.d_SLUG_date">Oct 17, 2026</span>
  <span class="nextup-date-what" data-i18n="nextup.d_SLUG">What happens, short</span>
  <span class="nextup-chip nextup-chip-row"><span data-days-until="YYYY-MM-DD">0</span>&nbsp;<span data-i18n="nextup.days_word">days</span></span>
</li>
```
Rules:
- `data-past-after` = last day of the event or deadline (the row grays out the morning after). `data-days-until` = first day.
  For a single-day event both are the same date. Format `YYYY-MM-DD`.
- NEVER put `data-days-until` on an element that also has `data-i18n` (it wipes the label). Copy the chip exactly as above.
- The Election Day row keeps its extra class `nextup-date-row-eday`; do not touch it or the five existing rows.
- Triple-edit rule: the same English text goes in three places: the `<span>` fallback text above, `src/i18n/en.json`
  `nextup.d_SLUG_date` and `nextup.d_SLUG`, and Spanish in `src/i18n/es.json` for the same two keys. Key names `d_SLUG` use
  underscores, short, unique, not already in `nextup`.
- Date label formats: English "Oct 17, 2026" or "Oct 17 to 19, 2026"; Spanish "17 oct 2026" or "17 al 19 de oct 2026".
- The row text is one short line, no emdashes. The source link lives in `events.json`, not the ledger row.
- Edit JSON with a script (keep key order, 2-space indent, `ensure_ascii=False`, trailing newline), e.g. load, add keys inside
  `["nextup"]`, dump. Do not hand-edit commas.
Do not remove old rows; they gray out on their own.
